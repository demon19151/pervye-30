# Первые 30

**Не проходи первый месяц в одиночку.**

Каждый день — маленький шаг, поддержка группы и внимание к своему состоянию.

«Первые 30» — платформа для прохождения первых 30 дней важного жизненного или рабочего этапа
вместе с небольшой группой и куратором. В этом MVP реализован один сценарий:
**«Первые 30 дней на новой работе»**.

Участник каждый день получает небольшое задание, отмечает выполнение, проходит чек-ин настроения
и энергии, общается с группой. Куратор видит прогресс каждого и получает ненавязчивый сигнал,
если участнику может понадобиться поддержка.

## Запуск

```bash
npm install
npm run dev
```

Приложение откроется на [http://localhost:3000](http://localhost:3000).

Сборка production-версии:

```bash
npm run build
npm run start
```

## Демонстрационный доступ

| | |
| --- | --- |
| **Код группы** | `P30WORK` |
| **Роли** | «Участник» и «Куратор» — выбираются на экране входа |
| **Участники** | Анна, Максим, Ирина, Дмитрий |
| **Куратор** | Елена |

На странице `/join` достаточно ввести имя (например, **Анна**), код **P30WORK** и выбрать роль.
Любое другое имя тоже подойдёт — будет создан новый профиль участника.

Роль и «текущего участника» можно переключать на ходу: блок с именем внизу бокового меню,
либо страница «Профиль» на мобильном.

## Демонстрационный путь за 2–3 минуты

1. Лендинг `/` → **Создать группу**.
2. Форма: название, описание, длительность → **Создать группу**.
3. Появляется код приглашения **P30WORK** и список заданий → **Перейти в панель куратора**.
4. Вход `/join`: имя **Анна**, код **P30WORK**, роль **Участник** → **Войти**.
5. Dashboard участника: **День 7 из 30**, задание «Подвести итоги первой недели».
6. **Выполнено** → прогресс растёт, появляется тост.
7. Чек-ин: настроение **4/5**, энергия **4/5**, заметка → **Сохранить день**.
8. Сообщение в карточке «Группа» → появляется в ленте, работают реакции ❤️ 👏 🔥 👍.
9. Переключение роли на **Куратор** (блок с именем в боковом меню).
10. Панель куратора: таблица участников — Анна активна, у Максима пропуск, Ирине нужна
    поддержка, Дмитрий активен.
11. Блок **«Требуют внимания»**: «Ирина — участнику может понадобиться поддержка» →
    **Написать Ирине**.
12. Итог: **Первые 30 = задание + состояние + группа + куратор.**

## Логика сигналов поддержки

Куратор видит участника в блоке «Требуют внимания», если срабатывает одно из условий:

- **A.** Участник не отмечал задания **3 дня подряд** (дополнительно — мягкий сигнал при двух
  и более пропущенных днях).
- **B.** Среднее настроение или энергия за последние 3 чек-ина **не выше 2.5**.
- **C.** Участник сам нажал **«Нужна поддержка»**.

В интерфейсе используется только формулировка **«Участнику может понадобиться поддержка»**.
Это социальный сигнал внимания для куратора, а не оценка состояния человека и не медицинская
функция. Пороговые значения собраны в `lib/services/statsService.ts`.

### Как считается прогресс

Прогресс — это выполнение программы **к текущему дню участника**, а не ко всем 30 дням:
задания весят 70%, чек-ины — 30%. Поэтому участник, идущий по графику, видит 100%,
а пропуски заметно снижают значение. Текущий день участника — первый день без чек-ина,
ограниченный текущим днём группы: за счёт этого Анна находится на дне 7, Максим — на 6,
Ирина — на 5. Все сводные цифры (средний прогресс группы, количество выполненных заданий)
считаются из этих же данных, поэтому таблицы и карточки всегда согласованы между собой.

## Хранение данных

Состояние приложения — единый снимок `AppState` в `localStorage` (ключ `pervye-30:state`).
Все изменения проходят через чистые функции сервисов: `service(state, input) → state`.
Единственное место, знающее о способе хранения, — `lib/storage.ts`.

Чтобы подключить Supabase или PostgreSQL, достаточно заменить реализацию `loadState`/`saveState`
на сетевые вызовы (или переписать сервисы на запросы к API) — типы, компоненты и страницы
менять не нужно.

Сбросить демо-данные можно в «Настройках» куратора, в профиле участника или через блок с именем
в боковом меню.

## Технологии

Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · Lucide Icons.
Собственные UI-примитивы в стиле shadcn/ui, без дополнительных зависимостей.

Интерфейс адаптирован под desktop, tablet и mobile: на мобильном — нижняя навигация,
карточки на всю ширину, крупные зоны нажатия, боковое меню в раскрывающейся панели,
а таблица участников превращается в список карточек.
